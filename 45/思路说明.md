# 跳跃游戏 II - 算法思路详解

## 问题分析

给定一个长度为 n 的 0 索引整数数组 nums。初始位置在下标 0。
每个元素 nums[i] 表示从索引 i 向后跳转的最大长度。
返回到达 n - 1 的**最小跳跃次数**。测试用例保证可以到达 n - 1。

### 核心思想

与跳跃游戏 I 不同，这里需要求**最小步数**，而不是能否到达。
关键在于：**在每一步中，选择能跳得最远的位置作为下一步的起点**。

---

## 方法1：贪心算法（推荐）

### 核心思路

维护两个关键变量：
1. **max_reach**：当前能到达的最远位置（全局最优）
2. **end**：当前步数能到达的最远位置（当前步数的边界）

算法流程：
1. 遍历数组（不需要遍历最后一个位置）
2. 对于每个位置 i：
   - 更新 `max_reach = max(max_reach, i + nums[i])`
   - 如果 `i == end`（到达当前步数的边界）：
     - 增加一步：`jumps += 1`
     - 更新边界：`end = max_reach`
     - 如果 `end >= n-1`，提前返回

### 为什么这样做是正确的？

**关键洞察**：
- 当我们到达当前步数的边界 `end` 时，说明必须再跳一步才能继续前进
- 在到达边界之前，我们一直在"探索"下一步能到达的最远位置
- 一旦到达边界，我们就用探索到的最远位置作为新的边界

**贪心策略的正确性**：
- 在每一步中，我们总是选择能跳得最远的位置
- 这保证了用最少的步数到达目标
- 因为如果某个位置能到达，那么它之前的所有位置也都能到达

### 执行示例

**示例1：`[2, 3, 1, 1, 4]`**

```
初始: jumps=0, max_reach=0, end=0

位置 0: nums[0]=2
  更新 max_reach: max(0, 0+2) = 2
  到达边界 i == end (0 == 0)，增加步数: jumps = 1
  更新边界: end = 2

位置 1: nums[1]=3
  更新 max_reach: max(2, 1+3) = 4
  未到达边界 (1 != 2)，继续

位置 2: nums[2]=1
  更新 max_reach: max(4, 2+1) = 4
  到达边界 i == end (2 == 2)，增加步数: jumps = 2
  更新边界: end = 4
  end (4) >= 最后一个位置 (4)，提前返回

结果: jumps = 2 ✓
```

**示例2：`[2, 3, 0, 1, 4]`**

```
初始: jumps=0, max_reach=0, end=0

位置 0: nums[0]=2
  更新 max_reach: max(0, 0+2) = 2
  到达边界，jumps=1, end=2

位置 1: nums[1]=3
  更新 max_reach: max(2, 1+3) = 4
  未到达边界，继续

位置 2: nums[2]=0
  更新 max_reach: max(4, 2+0) = 4
  到达边界，jumps=2, end=4
  end >= 4，提前返回

结果: jumps = 2 ✓
```

### 复杂度分析

- **时间复杂度**：O(n) - 只需遍历一次数组
- **空间复杂度**：O(1) - 只用了常数个变量

## 方法2：从后往前贪心

### 核心思路

从最后一个位置开始，每次找能到达当前位置的最远位置。

算法流程：
1. 从位置 `n-1` 开始
2. 从前往后找能到达当前位置的最远位置 `i`
3. 将 `position` 更新为 `i`，步数加 1
4. 重复直到 `position == 0`

### 为什么这样做是正确的？

- 如果我们能找到一个位置 i 能到达目标位置，那么从 i 到目标位置只需要一步
- 这样我们可以逐步向前找，每次找最远的位置，保证步数最少

### 复杂度分析

- **时间复杂度**：O(n²) - 最坏情况下每个位置都要遍历前面的所有位置
- **空间复杂度**：O(1)

## 错误代码分析

### 错误代码

```python
minstep = 0
maxrea = 0

if nums[0] < len(nums):
    for i in range(0, len(nums) - 1):
        if maxrea < i + nums[i] and i + nums[i] < len(nums):
            minstep += 1
        maxrea = max(maxrea, i + nums[i])

return minstep
```

### 主要问题

#### 1. **逻辑错误：条件判断不正确**

```python
if maxrea < i + nums[i] and i + nums[i] < len(nums):
    minstep += 1
```

**问题**：
- 这个条件会在每次能扩展范围时都增加步数
- 但实际上，我们应该在"到达当前步数的边界"时才增加步数
- 例如对于 `[2, 1, 1, 1, 4]`：
  - i=0: maxrea=0, 0+2=2, 条件满足，minstep=1, maxrea=2
  - i=1: maxrea=2, 1+1=2, 条件不满足，minstep=1, maxrea=2
  - i=2: maxrea=2, 2+1=3, 条件满足，minstep=2, maxrea=3
  - 结果：2（碰巧对了，但逻辑不对）

#### 2. **边界条件错误**

```python
if nums[0] < len(nums):
```

**问题**：
- 如果 `nums[0] >= len(nums)`，代码直接返回 0
- 但即使 `nums[0] >= len(nums)`，也应该能到达（一步就能到）
- 例如：`[5]` 应该返回 0，`[10, 1, 1]` 应该返回 1，而不是被这个条件限制

#### 3. **限制条件错误**

```python
i + nums[i] < len(nums)
```

**问题**：
- 如果 `i + nums[i] >= len(nums)`，说明能直接到达或超过最后一个位置
- 这是好事，不应该被排除
- 例如：`[2, 1]`，从位置 0 跳 2 步能直接到达位置 2（超过最后一个位置），应该算作能到达

#### 4. **缺少边界检查**

- 没有处理数组长度为 1 的情况
- 如果数组长度为 1，应该返回 0（已经在最后一个位置）

### 正确的思路

应该维护**当前步数的边界**，而不是简单地判断能否扩展范围：

```python
jumps = 0
max_reach = 0
end = 0  # 当前步数能到达的最远位置

for i in range(n - 1):
    max_reach = max(max_reach, i + nums[i])
    
    if i == end:  # 到达当前步数的边界
        jumps += 1
        end = max_reach
        
        if end >= n - 1:
            break

return jumps
```

## 方法对比与选择

### 推荐使用方法1（贪心算法）

1. **时间复杂度最优**：O(n)
2. **空间复杂度最优**：O(1)
3. **逻辑清晰**：维护边界的概念直观易懂
4. **可以提前返回**：效率高

### 方法2虽然也能解决问题，但：

- 时间复杂度更高：O(n²)
- 实现相对复杂
- 适合需要记录路径的场景

## 关键理解点

### 1. 为什么需要维护两个变量？

- **max_reach**：记录全局能到达的最远位置（探索结果）
- **end**：记录当前步数能到达的边界（当前限制）
- 当到达边界时，用探索到的最远位置更新边界

### 2. 为什么在 i == end 时增加步数？

- 到达边界意味着必须再跳一步才能继续前进
- 在边界之前，我们一直在探索下一步能到达的最远位置
- 一旦到达边界，就用探索到的最远位置作为新的边界

### 3. 为什么不需要遍历最后一个位置？

- 如果我们在遍历过程中已经能到达最后一个位置，会提前返回
- 如果遍历完所有位置，最后一个位置肯定能到达（题目保证）
- 遍历最后一个位置没有意义，因为我们不需要从最后一个位置再跳

### 4. 边界情况处理

- **数组长度为 1**：已经在最后一个位置，返回 0
- **第一个位置就能到达最后**：在循环中会提前返回
- **需要多步才能到达**：正常遍历，每次到达边界时增加步数

---

## 与跳跃游戏 I 的区别

| 特性 | 跳跃游戏 I | 跳跃游戏 II |
|------|-----------|-----------|
| 问题 | 能否到达最后一个位置 | 到达最后一个位置的最小步数 |
| 方法 | 维护能到达的最远位置 | 维护当前步数的边界 |
| 复杂度 | O(n) 时间，O(1) 空间 | O(n) 时间，O(1) 空间 |
| 关键变量 | max_reach | max_reach + end |
