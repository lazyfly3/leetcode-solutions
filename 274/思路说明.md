# H 指数 - 算法思路详解

## 问题分析

给定一个整数数组 citations，其中 citations[i] 表示研究者的第 i 篇论文被引用的次数。
计算并返回该研究者的 h 指数。

**h 指数的定义**：
- 至少发表了 h 篇论文
- 至少有 h 篇论文被引用次数 >= h
- 如果 h 有多种可能的值，h 指数是其中最大的那个

### 核心思想

我们需要找到最大的 h，使得至少有 h 篇论文的引用次数 >= h。

---

## 方法1：排序后遍历（推荐）

### 核心思路

1. 将数组从大到小排序
2. 遍历排序后的数组
3. 对于位置 i（从 0 开始）：
   - 如果 `citations[i] >= i + 1`，说明至少有 `i + 1` 篇论文引用次数 >= `i + 1`
   - 更新 `h = i + 1`
   - 继续遍历，直到不满足条件

### 为什么这样做是正确的？

**关键洞察**：
- 排序后，前 i+1 篇论文的引用次数都 >= citations[i]
- 如果 citations[i] >= i+1，说明这 i+1 篇论文的引用次数都 >= i+1
- 因此 h 至少为 i+1

**贪心策略的正确性**：
- 我们从大到小排序，优先考虑引用次数高的论文
- 每次检查是否满足更大的 h 值
- 找到最大的满足条件的 h

### 执行示例

**示例1：`[3, 0, 6, 1, 5]`**

```
原数组: [3, 0, 6, 1, 5]
排序后: [6, 5, 3, 1, 0]

位置 0: citations[0] = 6
  6 >= 1? 是，h = 1

位置 1: citations[1] = 5
  5 >= 2? 是，h = 2

位置 2: citations[2] = 3
  3 >= 3? 是，h = 3

位置 3: citations[3] = 1
  1 >= 4? 否，停止

结果: h = 3 ✓
```

**示例2：`[1, 3, 1]`**

```
原数组: [1, 3, 1]
排序后: [3, 1, 1]

位置 0: citations[0] = 3
  3 >= 1? 是，h = 1

位置 1: citations[1] = 1
  1 >= 2? 否，停止

结果: h = 1 ✓
```

### 复杂度分析

- **时间复杂度**：O(n log n) - 排序的时间复杂度
- **空间复杂度**：O(1) - 如果使用原地排序，否则 O(n)

## 方法2：计数排序

### 核心思路

适用于 citations 值较小的情况。

1. 创建一个计数数组 count，count[i] 表示引用次数为 i 的论文数量
2. 对于引用次数 >= n 的，都算作 n
3. 从后往前累加，找到最大的 h 使得至少有 h 篇论文引用次数 >= h

### 为什么这样做是正确的？

- 计数排序避免了排序的开销
- 从大到小累加，找到最大的满足条件的 h
- 时间复杂度更优，但需要额外的空间

### 复杂度分析

- **时间复杂度**：O(n)
- **空间复杂度**：O(n)

---

## 方法3：暴力法

### 核心思路

尝试所有可能的 h 值（从 0 到 n），找到最大的满足条件的 h。

### 复杂度分析

- **时间复杂度**：O(n²)
- **空间复杂度**：O(1)

---

## 错误代码分析

### 错误代码

```python
h = 0
temh = 0
m = len(citations) - 1

for i in range(0, m):
    num = 0
    if citations[i] < len(citations): 
        for k in range(0, m):
            if citations[k] >= citations[i]:
                num += 1
        if num >= citations[i]:
            temh = max(temh, citations[i])

return temh
```

### 主要问题

#### 1. **范围错误：漏掉了最后一个元素**

```python
m = len(citations) - 1
for i in range(0, m):  # 只遍历到倒数第二个元素
```

**问题**：
- `range(0, m)` 只遍历到 `m-1`，即倒数第二个元素
- 应该用 `range(len(citations))` 或 `range(0, len(citations))`

#### 2. **条件判断错误：限制了 h 的可能值**

```python
if citations[i] < len(citations):
```

**问题**：
- 这个条件限制了只考虑引用次数 < 数组长度的论文
- 但 h 指数可能等于数组长度（例如 `[100]` 的 h=1）
- 应该考虑所有可能的 h 值

#### 3. **逻辑错误：只考虑 citations 中的值**

**问题**：
- 代码只检查 `citations[i]` 作为可能的 h 值
- 但 h 指数不一定是 citations 中的某个值
- 应该尝试从 0 到 n 的所有可能的 h 值

#### 4. **效率问题：双重循环**

**问题**：
- 时间复杂度 O(n²)
- 可以用排序优化到 O(n log n)

#### 5. **边界情况：没有处理特殊情况**

**问题**：
- 如果数组为空，应该返回 0
- 如果所有论文引用次数都为 0，应该返回 0

### 正确的修正思路

应该：
1. 考虑所有可能的 h 值（从 0 到 n）
2. 对于每个候选 h，统计有多少篇论文引用次数 >= h
3. 如果至少有 h 篇论文引用次数 >= h，则 h 是有效的
4. 返回最大的有效 h

或者使用排序方法：
1. 将数组从大到小排序
2. 遍历排序后的数组，找到最大的满足条件的 h

---

## 方法对比与选择

### 推荐使用方法1（排序后遍历）

1. **时间复杂度合理**：O(n log n)
2. **空间复杂度最优**：O(1)（如果使用原地排序）
3. **逻辑清晰**：排序后直接遍历
4. **易于理解**：直观的贪心策略

### 方法2（计数排序）适用于：

- citations 值较小的情况
- 需要 O(n) 时间复杂度的场景

### 方法3（暴力法）适用于：

- 理解问题的本质
- 数据量很小的情况

---

## 关键理解点

### 1. 为什么需要排序？

- 排序后，我们可以按引用次数从高到低检查
- 如果前 h 篇论文的引用次数都 >= h，则 h 是有效的
- 排序使得检查过程更直观

### 2. 为什么检查 citations[i] >= i + 1？

- 排序后，前 i+1 篇论文的引用次数都 >= citations[i]
- 如果 citations[i] >= i+1，说明这 i+1 篇论文的引用次数都 >= i+1
- 因此 h 至少为 i+1

### 3. 为什么 h 指数是最大的满足条件的值？

- 题目要求：如果 h 有多种可能的值，h 指数是其中最大的那个
- 我们从大到小检查，找到的第一个不满足条件的位置，前一个位置就是最大的 h

### 4. 边界情况处理

- **数组为空**：返回 0
- **所有论文引用次数为 0**：返回 0
- **只有一篇论文**：如果引用次数 > 0，返回 1；否则返回 0
